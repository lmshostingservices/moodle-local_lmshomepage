Version 2.11.36  (2026-08-03)
------------------------------
FIXED: get_completion_report — quizzes now show Passed/Not Passed like assignments.
  A quiz whose completion rule is "mark complete on submit" stores
  completionstate=1 (Complete), while assignments with "require passing grade"
  store 2/3 — so the same cohort showed "Complete" on the quiz but Passed/Not
  Passed on the assignments. Step 8b now treats the gradebook "grade to pass"
  threshold as authoritative: when gradepass > 0 and a finalgrade exists, a plain
  Complete (or missing) record is upgraded to Passed (>= gradepass) / Not Passed
  (< gradepass). Native Pass/Fail records are untouched; the real completion date
  is preserved. Activities with no pass threshold keep their existing state.
  NOTE: the quiz must have a "Grade to pass" value set for pass/fail to derive.
No schema changes.

Version 2.11.34  (2026-07-31)
------------------------------
FIXED: get_completion_report — course-completion-criteria filter (Step 3b) is now
  STRICT. Previously, if the course_completion_criteria (criteriatype=4) query
  returned no rows, the report fell back to showing ALL completion-tracked
  activities — so non-criteria items (forums, practice quizzes) leaked in as extra
  columns. Now a successful-but-empty criteria query yields NO activity columns;
  an un-ticked activity is never listed. The "show all" fallback is retained only
  when the query throws (table missing/inaccessible).
IMPROVED: criteria matching hardened — moduleinstance is treated as a cmid (Moodle
  standard) and, if unmatched, resolved via (module, instance) → cmid.
No schema changes.

Version 2.11.33  (2026-07-31)
------------------------------
FIXED: get_completion_report — generalised the gradebook fallback (Step 8b) from
  quiz-only to ALL graded completion-criteria activities. v2.11.31 only rescued
  quizzes (grade_items.component='mod_quiz'), so assignments, SCORM, workshops,
  lessons and H5P criteria rendered blank for students who completed them before
  activity-completion tracking was enabled. Step 8b now matches every activity
  grade item (itemtype='mod') back to its cmid via (itemmodule, iteminstance) and
  applies the same Pass/Not Passed/Complete derivation. Existing
  course_modules_completion records are never overwritten.
No schema changes.

Version 2.11.32  (2026-07-31)
------------------------------
FIXED: get_completion_report — replaced get_records_sql() with get_recordset_sql()
  in Step 8a and Step 8b. get_records_sql() keys rows by the first column, so
  Step 8a (userid first) kept only ONE completion record per student and Step 8b
  (quiz_instance first) kept only ONE student's grade per quiz — the grade
  fallback effectively returned nothing. Recordsets iterate every row with no key
  collision.
No schema changes.

Version 2.3.3  (2026-04-01)
------------------------------
FIXED: Scheduled task "Attendance KPI check and escalation notifications" failing
  with "Task failed" on all sites. Root cause was two unguarded exception paths:

  1. Orphaned attendance records (course deleted but attendance row still in DB).
     context_course::instance() and get_course() both throw a hard moodle_exception
     when the course no longer exists. With no try-catch around the foreach loop,
     the very first orphaned row killed the entire task and Moodle marked it failed.
     Fix: added $DB->record_exists('course', ...) guard before each attendance;
     orphaned rows are now skipped with a clear mtrace message.

  2. message_send() throwing (e.g. message provider not flushed after upgrade).
     Fix: wrapped message_send() in try/catch(\Throwable) so a bad send logs a
     warning and continues rather than propagating back to the task runner.

  3. Outer loop now wrapped in try/catch(\Throwable) as a belt-and-braces backstop
     so any other unexpected exception is logged and the task continues processing
     the remaining attendance records.

  Task now prints a completion summary: "Checked: X, skipped/errored: Y".
